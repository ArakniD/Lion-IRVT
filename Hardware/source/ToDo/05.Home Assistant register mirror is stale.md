## Update the Home Assistant integration's register mirror to the v2.1 map

`lion-lvrt-integration`'s register mirror is still a transcription of the **v1**
map. The C2000 moved to v2 (2026-09-19) and then compressed the settings block
(v2.1, 2026-09-22); neither reorder reached this file. The ESP32's own mirror
(`esp32-btle-proxy/.../bts_regs.h`) **was** updated and is a correct reference
for everything except its stale header comment.

Found while implementing ToDo 01. Out of that ToDo's scope, recorded here
rather than fixed in passing.

### Severity

**The integration cannot currently read any unit-level register correctly.**
Every unit address it holds is 192 bytes high, so a read of `eUnitState` lands
on `eCh6_VoutOffset_pu` and returns a calibration coefficient as a state enum.
Settings reads are worse: the stride is wrong as well as the base, so a
per-slot settings read walks off into another slot.

17 tests in `tests/test_registers.py` already fail on this. They are correct
and the mirror is wrong - **do not adjust the tests to match the mirror.**

### What is wrong

| Constant | Mirror holds | C2000 has |
|---|---|---|
| `UNIT_BASE` | 1152 | **960** |
| `SET_STRIDE` | 96 | **72** (18 registers, not 24) |
| `TOTAL_REGISTERS` | 315 | **267** |
| `TOP_ADDRESS` | 1256 | **1064** |
| every `REG_*` unit address | 1152-1256 | **960-1064** |

The runtime block is unaffected: base 0, stride 48, 12 registers per slot in
both.

The settings block lost six registers per slot in the v2.1 compression, which
is where the stride change comes from. Charge and discharge limits were merged
into one pair, and the minimum cell temperature was dropped:

| Mirror offset | C2000 offset |
|---|---|
| `SET_MODE` 0 | 0 |
| `SET_CHARGE_V_MIN` 4, `SET_DISCHARGE_V_MIN` 12 | merged to `V_MIN` **4** |
| `SET_CHARGE_V_MAX` 8, `SET_DISCHARGE_V_MAX` 16 | merged to `V_MAX` **8** |
| `SET_CHARGE_I_MIN` 20, `SET_DISCHARGE_I_MIN` 28 | merged to `I_MIN` **12** |
| `SET_CHARGE_I_MAX` 24, `SET_DISCHARGE_I_MAX` 32 | merged to `I_MAX` **16** |
| `SET_MIN_CELL_TEMP` 36 | **removed** |
| `SET_MAX_CELL_TEMP` 40 | **20** |
| `SET_CAL_FIRST` 44 | **24** |

The 12 `CAL_*` offsets keep their internal order and stay relative to
`SET_CAL_FIRST`, so those do not change.

### Scope

- `custom_components/lion_lvrt/protocol/registers.py` - the mirror itself.
- Anything that indexes it. The merged charge/discharge limits mean a caller
  that wrote `SET_CHARGE_V_MAX` and `SET_DISCHARGE_V_MAX` separately now has
  one register to write, which is a **semantic** change, not just an address
  change - check `coordinator.py`, `number.py`, `sensor.py` and the config
  flow for callers that assume the two are independent.
- `tests/simulator/unit.py` if it models the settings block by offset.
- `tools/` and any HA-side documentation carrying addresses.

### Authority

`registers.h` is authoritative. Fix the mirror against it, never the reverse.
`esp32-btle-proxy/.../bts_regs.h` is a correct second opinion for the address
values, but note the two files use **different conventions** for the same
identifier families - the ESP32 uses byte offsets and bit masks where the
C2000 uses register indices and bit positions. Copying a line between them
compiles and is silently wrong. See the collision table in
`Docs/api-specification.md` §2.11.

`esp32-btle-proxy/.../bts_regs.h:53` still comments "unit mixed base 1152"
while its own `BTS_UNIT_BASE` is 960. The comment is stale, the value is
right; fix the comment while here.

### Verification

`tests/test_registers.py` must pass in full - it checks the mirror against the
C2000 enum address by address, which is exactly the drift that caused this.
Then the whole suite.

No hardware is required to fix or verify this.
