## Update the CANBUS telemetry for slot 1-8 - Pack voltage, current, mAh and mWh into single packet

Byte 0: Slot index and run state bitset
--Bits 0-3 Slot number 0-7
--Bits 4-7 Charging:Discharging:Paused:Fault
--- Charging is in charge mode
--- Discharging is in discharge mode
--- Paused if the slot is in paused mode, charge and discharge flags can be set
--- Fault for any hardware trips or faults on the slot preventing action
Byte 1-2: Voltage
--- 16bit value in mV (signed)
Byte 3-4: Current
--- 16it value in mA (signed)
Byte 5-7: mAh and mWh as 12 bit values
--- Byte 5 + byte 6[0:3] = mAh / 4 aka maximum 16,384 mAh
--- Byte 6[4:7] + byte 7 = mWh / 16 aka maximum 65,535 mWh

### Decisions taken where the spec left room

- **Byte order** is little-endian for the two 16-bit measurement fields,
  matching the mailbox's existing float word order rather than the I2C bus's
  big-endian convention.
- **Saturation, not wrapping**, on both accumulators. A counter that rolled
  over would read as a fresh test rather than a finished one, so the decoder
  also exposes `mah_saturated` / `mwh_saturated` to distinguish a floor from
  a measurement.
- **`PAUSED` does not replace the direction bit.** The spec says "charge and
  discharge flags can be set" while paused; this is implemented so a listener
  can always see what a resume would do, matching the status word.
- **`FAULT` is wider than an over-current trip.** It covers the trip, reverse
  polarity, a group disconnect and a strap-disabled slot - the four states
  that stop a slot from acting. A host that needs to tell them apart reads
  the status word.
- **State bits are composed on CPU1**, not re-derived on CPU2 from the packed
  status word, so there is only one encoding of the same thing.

### Breaking change

The old and new frames are indistinguishable on the wire. Any external host
decoding CAN telemetry must be updated together with the firmware. The
in-tree decoder was updated as part of this work; a third-party listener
would not be.
