## Enable SFRA at runtime from the MODE strap, instead of compiling it out

Deferred from ToDo 06, which completed the slot-tuning registers. This is the
other half: making SFRA selectable on a running unit rather than a build-time
`#define`.

## BLOCKED - the mode table has a conflict to resolve first

ToDo 06 states MODE `0b000` is unused and should select SFRA. The code
disagrees, in a way that matters:

- `registers.h:1032` maps mode 0 to `eModeIndependent` - 8 independent slots.
  It is a real, documented mode, and the low two bits of the mode carry the
  group size, so 0 is structurally "group of 1".
- The MODE and ENABLE straps are **pulled high**, so an unstrapped board reads
  `0b111`, which `truth_table[7]` in `bts_hal.c` maps to **0**. The comment on
  that entry says "Input 0=L or ALL OFF".

So mode 0 is simultaneously the independent-slots mode and the value an
unstrapped unit boots with. **Assigning SFRA to it would put every unstrapped
board into calibration mode at power-on**, with the AT console replaced by the
SFRA serial port and no slot running.

Decide one of:

1. Give SFRA a different MODE value and leave 0 as independent-slots.
2. Re-map the truth table so the unstrapped default is a safe mode other
   than the SFRA one.
3. Require SFRA mode to be confirmed by something beyond the strap - an EN
   combination that cannot occur unstrapped, or a register write.

## Then, the implementation

- `BTS_SFRA_ENABLED` is currently a compile-time `#define (false)` read at ~20
  `#if` sites, including the injection points inside `BTS_ctrlISR()`
  (`bts.h:574`, `:620`, `:670`) and the ISR wiring in `bts_cpu1.c` and
  `bts_hal.c`. A runtime switch means the injection has to compile in
  unconditionally and be gated on a variable, which puts a branch in the
  control ISR - measure the cost before committing to it.
- SFRA takes **SCIA**, which is also the AT console (`BTS_CONSOLE_ENABLED`)
  and, in a production build, the WS2812B LED driver's output. All three
  cannot hold it at once; the switch has to hand the port over and back.
- The slot under calibration is selected by the EN straps, per ToDo 06.
- `BTS_SFRA_CAPTURE_SETTINGS` is already defined for the CCCV branch (done in
  ToDo 04), so the SFRA block will compile once enabled. `VSET_VOUT` is the
  capture point chosen for a voltage loop.
- The results of a sweep are computed externally and written back through the
  slot-tuning registers at 1068-1116, which already exist and persist - that
  half is done.

## Verification

Both cores via `buildProject` / the approved gmake, both maps checked, and the
ESP32. On hardware: that entering SFRA mode does not disturb a running slot,
and that leaving it restores the console.
